AniDeck

Organizador pessoal de animes. Construí sozinho, com ajuda de IA, e mantenho no ar numa VPS própria.

papel · projeto pessoal feito com · apoio de IA backend · Go 1.26 + chi frontend · React 19 + Vite dados · PostgreSQL + RLS código · github.com/JoaoMendes1/anideck
01 · contexto

O problema

Eu queria uma lista que mostrasse o que já assisti, o que está pela metade e o que quero ver, atualizada sozinha. Os dados de catálogo vêm de uma API pública, a AniList, que tem limite de uso e já ficou fora do ar várias vezes. Boa parte do projeto foi aprender a não depender dela.

02 · arquitetura

Três decisões e o que elas custaram

Validar JWT por JWKS, não por segredo compartilhado

contextoO login é do Supabase; o backend em Go precisa confiar no token sem chamar o Supabase a cada request.
escolhiBuscar a chave pública via JWKS e validar o token no próprio backend.
descarteiValidar com um segredo compartilhado. Funcionava, mas o mesmo segredo precisaria existir em todo serviço que lê o token, e trocá-lo seria manual.
custoUma dependência a mais: se o endereço das chaves não responder, o login deixa de funcionar.

Isolamento por usuário no banco, com RLS — não no handler

contextoTodo dado é pessoal. Um filtro por usuário esquecido em um handler vaza a lista de outra pessoa.
escolhiRow Level Security no PostgreSQL, amarrado à identidade do token. O banco recusa o que o handler deixar passar.
descarteiConfiar só no código da aplicação. É mais rápido de escrever, mas um filtro esquecido vira vazamento sem nenhum aviso.
custoCada tabela precisa da sua regra, e entender por que "uma linha sumiu" leva mais tempo no começo.

Um interruptor para desligar a API externa, persistido no banco

contextoQuando a AniList fica instável ou o limite de uso estoura, preciso parar de consultá-la sem ter que fazer deploy.
escolhiFlag em memória para ser instantânea, espelhada no banco e relida no boot.
descarteiDeixar só em memória. A hospedagem gratuita que eu usava desligava o serviço sem tráfego, e a cada religada o interruptor voltava ao padrão.
custoUma leitura a mais ao iniciar, e o mesmo valor guardado em dois lugares, que precisam ficar iguais.

18 set 2026 · infra · 1 min

O free tier hiberna, e o seu estado em memória some junto

Eu tinha um interruptor no painel do AniDeck para cortar as chamadas à API externa quando ela degradasse. Funcionava: clicava, parava na hora. No dia seguinte, o painel mostrava desligado e o log mostrava requisição saindo.

A flag morava numa variável de pacote. No free tier o container hiberna sem tráfego e sobe do zero na próxima visita, com todo valor padrão de volta. O painel lia o banco; o backend lia a memória. Duas fontes de verdade que só divergiam de madrugada.

A lição geral: estado que precisa sobreviver a um restart não pode morar só no processo. E "restart" não é só deploy — é hibernação, OOM kill, migração de host. Todos acontecem sem você olhando.

A correção foi gravar a flag numa tabela de configuração e relê-la no boot. A memória continua sendo a fonte de leitura, porque precisa ser instantânea; o banco virou a fonte de verdade na inicialização.
