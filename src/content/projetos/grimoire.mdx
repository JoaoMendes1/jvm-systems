## O problema e o objetivo

Eu anotava palavras em inglês e não tinha onde guardar o termo, a tradução e a pronúncia juntos. O Grimoire resolve isso: digito o termo, ele traduz sozinho, gera o áudio, e eu organizo por categoria e estudo com flashcards.

Começou com SQLite, no próprio computador. Migrei para o Supabase quando precisei usar o mesmo vocabulário em aparelhos diferentes — e por isso ele é instalável no celular como aplicativo.

**Está em desenvolvimento.** Hoje é um caderno pessoal. O próximo passo é a revisão espaçada: o app passa a dizer o que revisar hoje, antes de a palavra ser esquecida. Virar produto para outras pessoas ainda é uma decisão em aberto.

## Como funciona

| Peça | O que é |
|---|---|
| **Navegador** | HTML, CSS e JavaScript sem framework, com Tailwind. Um service worker torna o app instalável (PWA). |
| **Servidor** | Go com chi. O mesmo binário serve os arquivos da tela e a API. |
| **Login** | Google, pela autenticação do Supabase. O servidor valida o token localmente, com a chave pública baixada no boot. |
| **Banco** | PostgreSQL no Supabase, acessado com SQL direto. O schema fica versionado em arquivos na pasta `sql/`. |
| **Serviços externos** | Tradução e voz do Google. |
| **Infra** | VPS com Docker e Caddy, e deploy a cada push na `main`. |

O caminho de uma palavra nova:

1. Digito o termo, e o navegador pede a tradução ao servidor, com o token de login.
2. O servidor valida o token e confere o limite de requisições.
3. Tenta o endpoint principal de tradução do Google. Se falhar, tenta o alternativo.
4. Se o termo digitado estava em português, refaz a chamada no sentido contrário: **o inglês é sempre o termo principal**.
5. Ao salvar, o servidor grava a palavra com o `user_id` do token. Toda consulta filtra por ele.

## Integrações externas

A tradução e o áudio vêm do Google, mas **não de uma API pública**: são endpoints internos, sem contrato e sem aviso de mudança. Usar isso exigiu decidir o que fazer quando eles falham.

| O que | Como foi tratado |
|---|---|
| **Instabilidade** | O endpoint principal de tradução falha de vez em quando. Há um segundo endpoint como alternativa: a falha vira lentidão em vez de erro. |
| **Bloqueio do IP** | Um laço no frontend podia esgotar a cota e fazer o Google bloquear o servidor, derrubando a tradução para todo mundo. Por isso as duas rotas que falam com o Google têm limite de requisições. |
| **Texto longo no áudio** | A voz do Google não lida com texto longo. Acima de 200 caracteres, o servidor devolve o endereço vazio de propósito, e o navegador usa a voz nativa dele. |
| **Risco que continua** | Qualquer um desses endpoints pode parar de responder num dia qualquer. É o motivo de a tradução estar planejada para sair do Google e ir para a IA. |

## IA no projeto

- **Planejado — worker de decodificação com o Gemini.** Colo a frase e a resposta é imediata; um processo separado corrige a grafia, traduz, escreve uma frase de exemplo e sugere um rótulo. Substitui os endpoints internos do Google por uma API com contrato.
- **Planejado — busca semântica com pgvector.** O mesmo worker gera o embedding de cada frase. Com ele, a ficha mostra frases parecidas e o app avisa sobre quase-duplicatas antes de gravar.
- **Por que a IA vem depois:** o worker sugere rótulo, então precisa de uma lista canônica de rótulos antes de existir. Sem ela, grava texto livre, e "Code", "Código" e "Golang" viram três coisas diferentes.

## O trecho que vale ler

É a função que substituiu a criação de tabelas no boot. O comentário conta o que deu errado antes dela.

<Terminal arquivo="internal/database/db.go">

```go
// InitDB abre a conexão e confere se o schema esperado existe.
//
// Ele NÃO cria nem altera tabela. O schema vive em sql/, versionado e aplicado à
// mão — ver sql/README.md. Até 19/09/2026 as tabelas eram criadas aqui com
// CREATE TABLE IF NOT EXISTS, e isso escondeu uma divergência por semanas:
// alguém alterou vocabularies.user_id para uuid no Supabase, o Go continuou
// declarando TEXT, e o boot seguiu anunciando "schema verificado com sucesso".
// IF NOT EXISTS cria, mas nunca altera.
func InitDB() error {
	dbURL := os.Getenv("DATABASE_URL")
	if dbURL == "" {
		return fmt.Errorf("variável de ambiente DATABASE_URL não foi definida")
	}

	var err error
	DB, err = sql.Open("postgres", dbURL)
	if err != nil {
		return fmt.Errorf("falha ao conectar ao supabase: %w", err)
	}

	// sql.Open não conversa com o banco: ele só valida os argumentos. Sem o Ping,
	// a primeira falha de conexão apareceria como erro de consulta no meio de uma
	// requisição, com o servidor já no ar dizendo que subiu.
	if err := DB.Ping(); err != nil {
		return fmt.Errorf("banco não respondeu: %w", err)
	}

	if err := conferirSchema(); err != nil {
		return err
	}

	fmt.Println("✅ Conexão e schema conferidos.")
	return nil
}
```

</Terminal>

## O que quebrou

| Sintoma | Causa e correção |
|---|---|
| **`user_id` com tipos diferentes no código e no banco, sem nenhum erro (19/09)** | O Go declarava `TEXT`, e a coluna tinha sido alterada para `uuid` direto no Supabase. Como o boot só criava tabela que não existia, nunca percebeu. Passei o schema para `sql/` e alinhei as duas tabelas em `uuid`. |
| **Variável de ambiente faltando aparecia como erro de banco** | A falha só surgia no meio de uma requisição. Hoje o servidor se recusa a subir se faltar qualquer uma das três variáveis obrigatórias. |
| **Tradução falhando de vez em quando** | O endpoint principal do Google é instável. Acrescentei um segundo endpoint como alternativa: a falha virou lentidão em vez de erro. |
| **Texto do usuário direto no HTML** | Termo e tradução são texto livre e iam para a tela sem tratamento, abrindo espaço para XSS. Todo texto do usuário passou a ser escapado antes de aparecer. |

## Conceitos que aprendi

| Conceito | O que é | Onde está |
|---|---|---|
| **Fail-fast** | Recusar subir quando falta configuração, em vez de falhar depois, no meio de uma requisição. | `cmd/web/main.go` |
| **JWKS** | Endereço com as chaves públicas que validam um JWT sem chamar o servidor de login a cada requisição. | `internal/middleware/auth.go` |
| **Token bucket** | Limitador que libera requisições num ritmo fixo e guarda uma reserva para picos. | `internal/middleware/rate_limit.go` |
| **Schema versionado** | Cada mudança no banco vira um arquivo numerado, aplicado em ordem e nunca editado depois. | `sql/` |
| **RLS** | Regra no próprio Postgres que decide quais linhas cada usuário vê. Aqui ela protege o acesso pela API do Supabase; a conexão do servidor ignora RLS, e o isolamento dela vem do filtro por `user_id`. | `sql/002_rls_policies.sql` |
| **XSS** | Texto digitado pelo usuário sendo interpretado como código na página. Evitado escapando o texto antes de exibir. | `static/app.js` |
| **PWA** | Site que o celular instala como aplicativo, com ícone e tela cheia. | `static/manifest.json` e `static/sw.js` |
